# 零目的LPのPhase I価格付け再検討

## 仮説と実装

PR66の静的正規化価格付けは全体では不利で棄却した。今回は主目的係数がすべて零であるLPだけを対象とし、従来のDantzig法を最初の1秒間維持する。それでもPhase Iが終わらず、利用可能な時間と反復予算が残る場合に限り、列の固定L1重みで被約費用を割った価格付けでcold restartする。問題名や既知解を判定に使わない。

正規化探索はmax(100, 8×行数)のピボット・上下限反転で打ち切り、数値失敗またはこの予算切れでは残りの総反復予算で従来法へ戻る。Phase IIとwarm startは従来方式を維持する。許容誤差、証明条件、元問題での解検査は変更しない。

## 棄却した途中案

最初から正規化する版では、零目的の生成LP 100設定で総ピボット3351→4431、合計時間0.040202→0.045978秒。大きめの別100設定でも17176→31546、0.297181→0.419640秒と悪化した。いずれも元MPSのFraction検査では全200出力が有効だった。ns1952667でも263→591ピボットとなったため、そのままの採用をやめた。

1秒の従来法を先行する現行版ではfhnw-binpack4-4、fhnw-binpack4-48、ns1952667の初回LPのピボット数を維持した。neos-3004026-krkaは従来法が10秒でLP点なし、現行版が3.41646秒・8380ピボットでLP点を得た。ここで得た点は連続緩和の点であり、整数実行可能解ではない。cryptanalysiskb128n5obj14は両方式とも10秒でLP点を得ていない。

## 比較上の注意と次の作業

開発188問題の10秒・1スレッド・16GiB比較と、元MPSに対するGMP絶対誤差/公式検査器およびFractionカット検査を実行中。holdoutは調整に使用しない。完了後に整数解・双対境界・終了状態を比較し、採否を決める。

途中のMIR有効/無効が一致していない比較、同一CPUで同時実行した時間測定、Mat RHS変更も含む比較は価格付け単独の性能根拠から除外するが、生データは残す。

swath1の追加numerical_errorは価格付け未発動だった。同一CPUでの再比較では変更前後の両方が同じ整数解・双対境界でnumerical_errorとなった。トレースは双対法で入る列を見つけられず実行不能証明も成立しない経路を示した。原因を価格付けと断定せず、raw statusを保持する。
