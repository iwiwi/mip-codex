# 局所不能方向を使うRENS固定緩和ヒント

main PR110上のRENS固定緩和の別試作。単純な共有行数の5%緩和はrococo/30n/co-100で主解改善がなかった。次案ではRENS local内だけcollect_conflictsを有効にし、局所B&BのLP不能方向を元の行へ戻し、元から固定された整数列の係数和が非零になる変数を収集する。固定値が0でも係数和を調べる。各不能方向で支持された回数順に最大4096候補を返す。

これは証明ではなく探索ヒントで、親の枝刈り・不能・下界・warm基底・pseudocostへ流用しない。局所MIP全体が不能で点なしの場合だけ再試行に使い、元のLP値で固定した変数のうちヒントが指す変数を優先して最大5%緩める。ヒントがある場合は有効なヒント数までに限定し、余分な近接変数を加えない。ヒントが空なら旧来の共有行順を使う。初回・収集・再試行は同じ全体10%・最大1秒の中で行う。

最上位のcollect_conflictsは既定falseでCLIに公開しない。RENS localだけtrueにするため、通常のMIPに係数走査や配列確保を追加しない。元Model、最終点の元問題検証、局所結果の分離は維持する。

4単体検査成功。0に固定された列が不能方向の支持に現れること、変数対応とrow符号、期限/長さの保守的拒否、局所不能後に実行可能点を得ること、親境界の不変性を確認した。全体検査・実行確認付き生成検査を経て同じ3問で比較する。新機能はまだ採用しない。

初版2e60904b794569c3は全291検査成功・生成800出力有効だったが、通常設定の局所LPでrow_sourcesを保持しておらず、実問題ではヒント0件だった。この選択測定をヒント方式の効果として数えない。collect_conflicts時は元行対応を明示保持し、局所不能後に点を得る統合試験でもconflict_hints>0を必須とした修正版の4検査が成功した。これから全体と実問題を再検査する。

main PR111統合・行対応保持版d6c21e65c1331df9は全293検査成功4無視、生成800出力も有効。実問題でヒントはrococo86・30n639・co-1004096件を得て41/373/2399変数を緩めたが、3問とも局所不能のままで主解改善なし。このヒント版も不採用として保存する。次案はfractionalな一般整数の床/天井制限自体を元の範囲へ戻す別設定で検査し、binary変数で変化しない場合の再試行は省略する。
