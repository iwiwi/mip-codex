# 次の仮説：切断行追加時の基底再利用

neos-860300の根LPは回復後でも約15秒かかる一方、現在prepare_cutsの最初のLPにもcut準備枠0.25秒を課しているため、このような根では切断候補を分離できない。元の根LPを解く時間と候補生成/追加後再最適化の時間を分ける必要がある。

先に、元列・目的・旧行係数のprefixが同じで、上側不等式だけを追加したProblemへWarmStartを拡張できるか検討する。新行のslackを基底に追加すれば、旧基底と新slackでblock下三角の基底を作れる。新slackの値は負でもよく、元の最適基底の双対乗数へ新行0を付ければ同じ目的でdual feasibleなので、既存の有界双対法で追加行を再最適化できる。

最初は元の列数/費用が同じ、旧equality/slack_upperと旧列のrow prefixが同じ、新行は不等式のみという保守的な条件。実装確認で旧slack/人工列は行ごとに混在していると分かったため、新slackを内部列末尾へ追加して旧indexをすべて維持し、親のArc構造/基底/Factorを変更しない。新しい疎LUで基底を再構築し、通常の元Problem/元MPS検査を維持する。条件不成立や失敗は従来のcoldへ戻す。

検証はcut追加のwarm/cold最適値、不能証明、人工変数を含む親、親/兄弟の不変性、費用/行/列変更によるfallback、ランダムLPのnative oracle。これが成功してからprepare_cutsを、最初の必要な根LPはglobal予算で一度解き、そのWarmStartを候補追加と主探索へ引き継ぐ方式へ分ける。neosだけの例外やnativeの解は使わない。固定18問の基底変化による主解悪化も比較する。
