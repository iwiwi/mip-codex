# 全ペア競合のclique cut：未採用

元行から証明した2変数coverを辺とし、全ペアが揃う符号付きliteral集合の和<=1を追加する。各辺を元行からRustとPython Fractionで独立に検査し、外側の全ペア・符号・右辺・重複も検査する。元行以外の追加cutへ依存しない。根の既存時間枠内で仕事量/辺数/行長/集合サイズを制限する。既定は無効。

Rust154テスト、200個の符号付きランダムgraphの全列挙（45cliques、180件の偽証明拒否）、一般合成2700、根LP300、桁落ち22・大整数10が合格。最後に、適格でない行を走査する場合もdeadlineを確認する修正を加え、clique単体テストと同じ200graphを新fingerprintで再検査した。200例を別の400独立例として数えない。

固定18問ではprimal/dual/statusすべて同一でclique追加0本。競合のありそうな開発6問（graph20-20-1rand、sorrell3、supportcase10/18、chromaticindex512-7、bnatt400）も追加0本で結果同一。うち2問は両側resource_limit、ほかも多くは根LPで時間切れ。MIPLIB上の改善を確認できないためmainへ採用しない。

保存26解はGMP絶対/公式検査ですべて有効。固定18問の134cuts/36証明記録と追加6問の128cuts/12証明記録も全件独立検査有効。これらは既存cover等の証明で、新cliqueがMIPLIBで効いた証拠ではない。

最初のclique単体fixtureでは1行に3組の列係数を記載してMPS parserに拒否された。入力形式を修正した後、正負clique・欠けた辺・重複辺・偽右辺・偽符号が所定の結果となった。失敗ログもartifacts/clique-evaluationへ保持する。

次は既存の座標修復が正の改善を見つけられない場合のbreakout重み更新を試す。証明/下界には使わず、最終候補は従来の元問題検査で受理する。
