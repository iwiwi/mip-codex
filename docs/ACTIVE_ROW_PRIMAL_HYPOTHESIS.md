# 原行の実行可能性部分MIPから元問題の主解を探す

主解だけを探す別研究。原行の一部と元の変数箱を持つMIPを自作Rustで解き、候補を全元制約/境界/整数性で検査する。不合格なら違反原行を足す。部分モデルの下界/状態/証明は元問題へ移さない。最初の診断は既存masterの行集合を使いsetup費用を含めていないため、main性能比較には使わない。

通常目的の診断20秒はmap10で目的0の元問題点を得たが45回の候補/違反行追加を要した。他3問は点なし。map10点は独立GMP絶対/公式補助で有効。目的を0へ変えた実行可能性版は、同じ事前集合から約0.24秒で同じ点を得た。さらに事前集合を完全に空にし、箱点の違反267行を追加するだけで、約0.52秒に同一の元問題点を得た。他3問は20秒で点なし。名前/既知解を使わない汎用手順であり、商品ソルバーへまだ入れていない。

次は原LPがworkspace上限を超え、主解がない根だけで実行する原行実行可能性MIP。元下端/0箱点から違反行を最大512追加、目的0の局所MIPを短い予算で解き、元問題全検査が通る点だけを返す。初回の空MIP solveは箱点生成へ置換して無駄な呼出しを省く。全体10%・上限1秒、同じ元deadline、局所node上限4096。既存LP/MIPヒューリスティックとrow-generation/reportを局所で止めて再帰しない。明示fixed-column無効を尊重し、それ以外は利用者の元の設定を子に復元する。

局所不能/最適/下界/基底/擬似コストは大域へ移さない。候補は元MPSのModel.check(true,1e-7)と既存の大域bound整合性検査を通す。統合後に全列挙/元点検査、原行追加が必要な反例、時間切れ/無効候補拒否を検査し、開発10/60秒の対照で確認する。既定無効で開始する。Master-bound PR113の源流から独立し、main再現/最終全件開始を遅らせない。
