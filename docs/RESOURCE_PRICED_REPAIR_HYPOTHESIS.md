# 資源制限後の主解を直接修復して改善する仮説

2026-11-17、未採用の診断専用案。既存のpriced_objective_repairは全変数binary・非負目的・10万変数以下に限る。resource_primalで得た混合型の境界点には適用されず、先の局所MIPによる端点同時固定試作も候補なしだった。

元点に正規化した目的改善行を1本追加した作業モデルを作り、既存のRust座標修復Repairを直接呼ぶ。整数・連続の扱いはRepair既存の処理を保持し、目的係数の符号や最大化は正規化する。探索対象の局所作業モデルは原モデルを変更しない。返った点は元問題の実行可能性と目的改善を再検査する。目的改善行の不能・数値状態や下界を原問題に転用しない。

最初は例プログラムのみで、保存済みの開発用主解から3秒、修復仕事量上限を指定し、原MPSのGMP検査まで実施する。準備時間込みのwallも別記する。改善がなければその事実を記録して棄却する。本体への有効化やMIPLIBの個別調整は行わない。

## 診断結果と次の試験

直接の既存Repairはmap10/map16715-04×seed0/1/2の6試行とも移動0・候補なし。仕事量4,877,140、準備込みwall約1.91秒。全ての改善単一移動が別の制約違反を増やすため、単調減少の条件で停止した。

既存修復を基にした診断専用Rust版で、局所停滞時に違反行の重みを2倍（上限あり）へ増やした。両問×3試行で全て0→-1、77移動・仕事量77,551,221、準備込みwall2.83〜2.89秒。全6点が元MPSのGMP絶対1e-6/目的rel1e-8と公式検査に合格。seed差が発生する前の同一決定的経路なので、6独立の確率的成功とは扱わない。

保存点-1からの続行はmap10で-2→-3、map16715-04で-2→候補なし。新3点もGMP/公式合格。各探索は3秒指定、準備は別でwall2.45〜2.79秒、仕事量上限1億。これはmain同一全体時間比較でも新記録でもない。

main120を基準とする別ブランチadaptive-resource-repairへ接続する。既定無効、`MIP_ADAPTIVE_RESOURCE_REPAIR=1`のみ。ルートの既存LP資源制限時に既知主解があれば、全体の20%かつ最大2秒・合計仕事量1億以内で改善を試す。作業モデル複製/入射情報の見積りを既存workspace予算以下に制限し、元LPの資源ガードは変更しない。全ての返却候補は元モデルの点・目的の信頼性を再検査、局所探索は下界/不能を返さない。

最大化・オフセット・負費用を正規化し、同じ作業モデルの目的改善行を更新して最大16段階試す。候補がなければ元主解を保持する。独立列挙/元MPS点検査/親証明検査/開発188対とnative比較が必要。現段階では本体採用も性能改善も未判断。
