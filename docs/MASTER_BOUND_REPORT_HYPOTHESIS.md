# 原行部分LPの乗数を元箱で再証明する

資源制限で原LPが作れない場合、元の原行を追加する部分LPは常に元LPの緩和である。安全な標準化で解いたmasterの双対乗数を元行へ戻し、元の変数箱・目的offset・十進係数の区間でCertifierにより別計算する。部分LPの点/状態を原MIPの最適性へ使うのではなく、下界表示だけを目指す。

初期の独立診断では、元問題の外側変数境界を使い、整数丸め/zero-dominance固定や局所分枝境界を仮定しない。選択原行と元変数メタデータからsubsetModelを作り、乗数の候補をraw、1±2^-40倍、2冪/固定格子へ丸めた13通りから試す。各候補は任意の乗数として区間再証明するため、乗数の近似自体を証明扱いしない。

開発4問を一律20秒、1thread、16GiB、従来512MiB workspace、CPU44で診断した。savsched1の元箱下界2.099999999999998から32.49999999995472、map10は−1675.0000000002258から−877.0805141714454。両問の全14候補は元MPSを別のFraction readerで読み、signed binary64乗数から正確なLagrangian下界を計算し、申告下界がそれ以下であることを誤差許容なしで確認した。整数点・最適性・新記録の主張はしない。

jaramaは診断上350.99999999998875、ns1760995は6masterとも有限の再証明なし。残り9件も独立有理数監査で有効と確認した。改善はまだ研究診断だけでmainへ未採用。既定を変更する前に、予算付きの表示専用実装、厳密schema/改竄拒否、全列挙/元問題点証明、10/60秒対照とnative比較、188開発対照を行う。holdoutは使わない。

採用候補には負結果の名目基底/代替点/予算拡張を含めず、安全な原行制約生成と下界再証明だけを移す。原LPと同じdeadline/pivot/memory上限を保ち、下界表示だけで枝刈り・最適性・不能宣言を変更しない。

表示専用の候補FPfeab7937b302312bを凍結した。既定有効の研究候補でありmain未採用、MIP_ROW_GENERATION=0で旧経路へ戻す。MIP_ROW_GENERATION_REPORT=0は新しい表示証明だけを止める。元LPメモリ概算上限を超える時だけ原行LPへ入り、証明再計算は全体5%・上限1秒の同じdeadline内で課金する。rootで生成cutモデルを使っていない時だけ報告し、元の外側変数箱で再証明するため局所固定の仮定を含めない。状態・枝刈り・最適性宣言には使用しない。

元の安全版FP784955e35c5f5989の10秒はsavsched2.1→26.49999999997751、map10−1675→−838.8513852875828、jarama0→285.9999999999931。6出力の証明は独立有効、点なし。60秒でもそれぞれ56.59999999990466/−689.3406401601442/400.9999999999862へ改善し、主解は両側なし。長時間の証明と最終指紋の再測定は別に全件検査する。

200全列挙MIPテンプレートのmin/max×off/on800出力は元問題の点/最適値/証明が全有効。354個の原行乗数証明が発行され、2832改竄を全拒否。正しさ試験は旧側512MiB/生成側1MiBと800非拘束行でguardを強制したもので、性能比較ではない。追加の小さいschema検査は2正常min/maxを受理し18改竄を拒否。全300 Rust成功4無視。最終指紋でも同じ200テンプレートを再検査する（独立問題数を倍に数えない）。

188開発×10秒をCPU16..20で開始。最初の監査はfrozen検査器のverify_master_bound import path不足でModuleNotFoundErrorとなったため、失敗記録を保全して監査だけを再実行した。再試行時にはpsの子無し終了値の取扱いでも失敗し、既存出力先への再起動で元console logを上書きした。各ケースのエラー/元解/点検査/比較測定は保持し、失敗理由をJSONへ明示した。ソルバー証明不正ではなく監査設定失敗として分離する。新監査はfrozen scriptsを先頭pathで読んで全出力を再検査する。
