# 一般整数ポンプの打切り点回収

基準は main a326be92a59eea70d31d057a7121a5ea9fef6746。11月16日の general-integer-pump 枝 d90b7799342175489df0c43124835a55eccf90a9 の自作ポンプと基底拡張を再利用する。旧試作は4問で解品質改善がなく不採用だった。今回の仮説は一般整数対応そのものではなく、現在のLP打切り点から整数丸め・元問題上の短い行修復で可行点を回収できること。

比較は同一バイナリ、同一資源で (A) 現main相当、(B) 一般整数ポンプのみ、(C) 一般整数ポンプ＋打切り点回収の3通り。既定はA。MIP_GENERAL_INTEGER_PUMP=1でB、加えてMIP_GENERAL_PUMP_LIMITED_RECOVERY=1でC。基底拡張はB/Cで共通。成功数を計測し、実際に使われない場合を区別する。二値専用経路は維持する。

L1距離用の補助変数・対の行を追加し、局所LPだけを解く。元の行・列、親基底、探索木の下界、枝刈りは変更しない。補助LPの目的値・双対・実行不能性は元MIPの証明に使わない。回収した点も既存の元モデル検査を通す。局所期限は現行の全体10%・最大1秒、64射影、各4096ピボット以内。修復は既存の全体残時間1%・最大100ms・作業上限500000を使う。対象は可動整数1024以下、元LP非零200000以下。

試験中の失敗も保存する。最初の回収テスト2回は共通prepare関数が基底を保持しないminimizeを使いnode.warm=Noneだったため、拡張成功数の前提に失敗した。実装の回収成否に到達していない。v3ではこのテスト内でminimize_warmを使って親基底を生成する。ログはinitial/v2/v3を保持する。
