# 原問題3行の厳密集約

2行の集約だけでは自由連続変数が残る場合に、3行の正整数結合で消去してCG丸めを得る仮説を試す。既存の2行経路を維持し、まず証明形式と独立検査を拡張する。まだmainの分離器は3行候補を生成せず、性能改善・採用は未定。

x,zが非負整数、t,uが自由連続として、3x+2t≤3、3u−t≤0、3z−6u≤1を重み1,2,1で合計すると3x+3z≤4。したがってx+z≤1を得る。どの2行を組み合わせても自由変数が残り、既存の丸めではこの不等式を得られない。x=1,z=1/3,t=u=0は元LPで実行可能だが新cutに違反する。

証明は元の異なる3行・有限の整数側・正整数重みのみを使う。i128のchecked演算と最終係数/RHSの2^52制限、元の変数境界/整数性の検査を維持する。RustとPython Fractionの両検査で3行を受理し、重み0、元行重複、名前改変、4行、RHS改変、不完全な消去を拒否する。上下側の符号反転と実行可能な整数点列挙も検査した。

次は候補2行に残った活動中の項を3行目で消す候補生成を独立に追加し、保存された開発LP点上で違反cutと証明を調べる。汎用MILPに有望なら、既存cutの後で試行LPを解き、実際の境界改善または有効整数点取得を確認したcutだけ残す。未検証のcutを下界や枝刈りへ使わない。問題名・既知解・holdoutを条件にしない。

候補生成器を追加し、既存2行経路では追加Vec確保を行わないiteratorを使った。古い保存LP点77件への検索予算20ms診断で16問題・258候補を得て、すべて元MPSのFraction証明検査に合格。並べ替えなどを含む実際の分離時間は一部20msを超えたためraw時間を保存する。

既存cut/MIR後のcacheに対してのみ3行候補を最大8本ずつ試し、LPを期限内に解いて相対境界改善1e-3以上または元問題の整数点を得た場合だけ保持する。改善なし/数値失敗/未完了/試行infeasibleでは元のcacheとモデルprefixを維持し、試行証明を大域判定へ昇格しない。probe/RINSでは無効とする。既定はfalseでMIP_THREE_ROW_CUTS=1で明示的に試す。

統合小例の初回テストは、強くなった根LP点が必ず整数になると誤って期待して失敗した。実際はcutが保持され、根境界−4/3→−1へ改善していた。根ではnode_limitでも正しいため、分枝後の整数最適解−1と元制約の維持を別に検査するよう修正した。212 Rust検査が通過。失敗ログも保存する。
