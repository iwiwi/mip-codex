# 箱端点の整数主解から根LPの実行可能基底を作る仮説

2026-11-16。cygnetは既存修復で元問題の整数点220を約0.16–0.25秒で得られる一方、冷たい根LPのPhase Iは60秒でも終わらない。純二値の主解では原変数がすべて箱端点にあるため、非基底変数の上限/下限状態と各行のslackを使い、Phase Iを経ずに実行可能な初期基底を作れる可能性がある。

次の研究候補。既存Standard変換で原点を内部変数へ写し、値が端点に一致する構造変数のみ非基底に置く。各行の独立な±1 slackを基底とし、等式ではゼロのartificialの扱いを既存Phase IIの規則と照合する。全基底/箱/残差を既存warm検査で再検証し、失敗時は従来coldへ戻す。変換後の行/aux列番号の対応、固定/自由/上限変数、原モデルの点/下界の検査が必要。許容誤差やpivot/deadlineは緩めない。

まだ未実装。PR79の採用判断後、既存の原目的箱下界表示の小修正を別途確認し、その後に根LPの冷/温対照と小例oracleから検査する。成分分割そのものは不要であり、主目標は汎用の自作LP性能改善である。

## 実装前のソース確認

Problemは全非等式を+1 slack付きの≤行として保持する。端点点が実行可能なら残差rhs−Axをそのslack基底へ置ける。等式はゼロの人工列を基底にしてupper=0とする候補。coldのRHS依存人工列配置を模倣する必要はなく、保持するStructure内のaux番号を一貫させる必要がある。WarmStartは現状dual-feasibleを想定し、cost_changed時だけprimal runへ進むため、新しい初期基底ではprimal-feasible経路を明示しなければならない。

scaling::solveは縮尺を決めてからrawを呼ぶため、基底生成は縮尺決定後のProblemで行い、点の内部座標も列縮尺へ変換する。既存warmがある場合はそちらを優先。新経路専用のfrom_point factoryとforced primal warmの薄いwrapperを候補とし、通常warm/cold経路を変えない。まず小さいLPの冷/温oracleと原点の厳密検査、期限/不適切点/内部点の拒否を確認する。まだ未実装。
