# 開発計画と再開手順

目標: 汎用Rust MILPソルバーでMIPLIB 2017 Benchmark Set v2全体をSCIP、HiGHS、GLPKと同条件で比較し、上回った後も改善する。期限: 2026-11-22 14:59 UTC (23:59 JST)。現時点で優位性は未達成。

## 不変条件
- LP緩和、前処理、分枝、カット、探索はRustで自作。既存最適化ソルバーへの委譲禁止。
- 問題名や既知解による分岐・調整は禁止。既存実装を移植する場合はライセンスと出典を記録。
- 解は元問題に対する独立したGMP有理数の絶対誤差検査器で検証する (Python浮動小数点は診断、公式相対検査は補助)。実行可能性と最適性の証明を区別。
- 数値異常、未対応、OOM、クラッシュを除外せず報告。誤答は採用不可。
- 日本語のコミット・PR・コメント。GitHub書き込み先はiwiwi/mip-codexのみ。
- 性能PRには比較結果とローカルログ由来の累積AIトークン使用量をコメントする。

## 実装順序
1. 評価資産と環境を固定。MPS読込、疎モデル、独立検査器。
2. 二段階単体法をRustで実装。小規模LP/MILPを全列挙・比較検証。
3. 分枝限定、伝播、整数丸め、ヒューリスティック。毎回正しさを回帰検証。
4. 疎改訂単体法、基底再利用、双対単体法。密表形式は検証用に残す。
5. カット、擬似コスト、強分枝、探索戦略を対照実験で改善。
6. 検証用セットと全240問の最終比較。open instanceへの改善は主ソルバーに統合。

## 現在の仮説
疎改訂単体法と親基底再利用は既定で有効。境界伝播は性能が混在したため既定無効。初期主解の丸め・座標修復と方向別擬似コスト分枝も検証して既定採用。探索順はfloor側を維持する。追加開発群の根LP数値エラーと微小目的係数による誤った最適宣言を修正。次はLP列スケーリングと非有界rayの追加検証、主解のLP潜り/feasibility pump、強分枝・カットによる下界強化を進める。個々の短期改善だけで全体の達成を主張しない。全240×3のbaselineは固定snapshotで実行中。新GMP primaryで保存解を別途再監査し、稼働snapshot/共有依存/CPU8..15を変更しない。

## 再開
`git status`、`docs/JOURNAL.md`、`docs/BENCHMARK.md`を読み、実ジョブPIDと終了状態を検査。ログだけでジョブが生存していると判断しない。失敗も記録し、採用変更はブランチ→PR→main。

## 長時間評価の時間予算

全比較720ケース×最大1時間÷8slotは最悪90時間。baseline開始11月15日03:28 UTCからの単純上限は11月18日21:28 UTC付近 (読込/検査等の追加時間を除く)。Rust240ケースは8slotなら最大30時間、4slotなら60時間。11月22日14:59 UTCの期限から逆算し、最終Rust全件runを遅らせすぎない。稼働slotのcgroup上限合計とホスト247GiBの余裕も確認する。

最終比較ではsnapshot固定、同じ1thread/時間/メモリ制限、元MPSへの有理数絶対検査、全失敗の一覧、完了後の参照値監査を必須にする。計測を先送りして開発用少数問題の改善だけで終わらせない。既定の伝播は無効、主解修復は検証後の採用判断をJOURNALに残す。
