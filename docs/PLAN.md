# 開発計画と再開手順

目標: 汎用Rust MILPソルバーでMIPLIB 2017 Benchmark Set v2全体をSCIP、HiGHS、GLPKと同条件で比較し、上回った後も改善する。期限: 2026-11-22 14:59 UTC (23:59 JST)。現時点で優位性は未達成。

## 不変条件
- LP緩和、前処理、分枝、カット、探索はRustで自作。既存最適化ソルバーへの委譲禁止。
- 問題名や既知解による分岐・調整は禁止。既存実装を移植する場合はライセンスと出典を記録。
- 解は元問題に対する独立したPython検査器で検証する。実行可能性と最適性の証明を区別。
- 数値異常、未対応、OOM、クラッシュを除外せず報告。誤答は採用不可。
- 日本語のコミット・PR・コメント。GitHub書き込み先はiwiwi/mip-codexのみ。
- 性能PRには比較結果とローカルログ由来の累積AIトークン使用量をコメントする。

## 実装順序
1. 評価資産と環境を固定。MPS読込、疎モデル、独立検査器。
2. 二段階単体法をRustで実装。小規模LP/MILPを全列挙・比較検証。
3. 分枝限定、伝播、整数丸め、ヒューリスティック。毎回正しさを回帰検証。
4. 疎改訂単体法、基底再利用、双対単体法。密表形式は検証用に残す。
5. カット、擬似コスト、強分枝、探索戦略を対照実験で改善。
6. 検証用セットと全240問の最終比較。open instanceへの改善は主ソルバーに統合。

## 現在の仮説
密表単体法は実装検証には有用だがMIPLIB規模ではメモリ・速度が律速となる。まず正しい参照実装と評価経路を確保し、疎基底へ移る。小規模な性能改善だけで全体の達成を主張しない。

## 再開
`git status`、`docs/JOURNAL.md`、`docs/BENCHMARK.md`を読み、実ジョブPIDと終了状態を検査。ログだけでジョブが生存していると判断しない。失敗も記録し、採用変更はブランチ→PR→main。
