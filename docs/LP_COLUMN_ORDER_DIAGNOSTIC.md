# 根LP数値エラーの列順依存性

2026-11-15 23:29 UTC。開発188問診断のnumerical_error9件を対象。元のCOLUMNSカードを変数単位で逆順へ並べ替え、他の行/RHS/RANGES/BOUNDS/目的カードは変えない。整数markerを再構成し、再解析した元MPS Fractionで全係数・行側・変数型/境界・目的が同じことを確認してから実行する。

同じPR58凍結Rust/1thread/16GiB/10秒/1節点で元順と逆順を2queueずつ、0..3の4コアで比較。cut/heuristic無効、MIP_LP_TRACEとcreate-new numerical dumpを有効にして停止段階を保存。新しい根点が出れば、列順後MPSだけでなく元MPSに対する連続LPのFraction検査へ回す。nativeソルバーは最適化に使わない。

これは診断であり、逆順でたまたま改善してもその問題名の順序を埋め込まない。統合する場合は任意の数値失敗に対する汎用の候補順序変更と元単位検査を通るものだけを検討する。許容差を弱めず、検証されない不能/非有界判定を採用しない。
