# 混合整数モデルの二値部分へのpump適用

一般整数変数が1つでも存在すると既存binary pumpが終了するため、その制限だけを取り除く小さい実験を行った。一般整数変数は距離目的から除外するが、候補では全整数変数を丸め、元問題の全境界・行・整数性を検査する。探索木や双対境界には使わず、既存の64反復と最大1秒の予算を維持する。

一般整数変数が整数に固定される混合モデルで有効候補を得ること、一般整数変数を0.5に固定する整数実行不能モデルで候補を拒否すること、どちらも親LPの基底を壊さないことをテストした。初期main69上で208 Rustテストが通過した。

10秒比較では、binkar10_1、pk1、timtab1、neos-911970、nu25-pr12の整数解と双対境界は一致した。timtab1では新たに64射影を試したが候補なし。追加の30n20b8、fiball、icir97_tensionでも64射影が整数解につながらず、約0.3～0.6秒の追加作業となった。

初期スクリプトの対象指定にholdoutのpgを含めてしまったが、split assertionがモデルパスの参照や読み込み・実行より先に停止した。その失敗ログも残す。既存の出力ディレクトリへの再実行もcreate-only検査で停止したため、別CPUの新しいディレクトリで実行した。

krkaは旧LP経路では60秒でも根LPが終わらず、この変更だけの効果を試せなかった。PR70の価格付けを含む基準版へrebaseし、同じ価格付けを有効にした変更前後で60秒比較を実行中。追加3問では価格付けを含めても整数解発見に至っていない。採用は未定で、得られた点の独立検査とkrkaの結果を待つ。

最終のkrka60秒比較も両側整数解なし・双対境界0だった。変更版は1回の射影LPで1.0044秒を消費し、候補なしで制限終了した。価格付けを含むRustテスト210件も通過したが、主解改善がなく時間を消費したため、この制限解除だけの案は棄却する。次は一般整数変数の距離目的と大きい射影LPの費用を検討する。

独立検査は26結果のカット/補助証明すべてと、保存された10整数解（GMP絶対誤差・公式）のすべてが有効だった。krkaの根LP点を変数種別別に調べると、一般整数130個はすべて整数値で、二値16900個のうち4160個が0.2だった。この点について一般整数の距離不足は原因ではなく、まず大きな二値射影の時間と対称な丸め対象を調べる必要がある。診断用Pythonの初回はバインディングの配列をループ内で繰り返し取り出して遅くなったため中断し、配列を一度だけ取り出す版で完了した。HiGHSはMPS読込だけに使い、最適化していない。
