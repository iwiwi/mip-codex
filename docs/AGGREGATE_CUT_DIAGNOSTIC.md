# 集約行の整数丸め：先に根点の診断

2026-11-15。PR56を基準とする。PR57のクリーク候補5案は終了時性能の上積みがなく未マージで閉じた。根上界31→26等の途中改善・全試行はそのbranchに保持する。

現在の丸め切断は単一元行の厳密整数係数とRHSから作る。次の仮説は複数元行の正の整数結合を作り、連続変数の係数を消去した後で既存と同じ床除算を適用すると、単一行で得られない違反切断が得られるというもの。まず自作Rust LPの根緩和点をcreate-new限定MIP_ROOT_LP_DUMPで記録し、Pythonの元MPS Fractionから候補を診断する。根LP点を整数実行可能解と呼ばない。nativeの解・重みをRust最適化へ渡さない。

候補の証明は元行の添字・側・正整数重み・divisorと原境界への投影を全て保存し、i128で安全に表現できないものは将来実装でも不採用にする。最適化への統合は診断で違反切断が得られてから別途判断する。初期は2行結合、共有連続変数の相殺または単純和から試す。既存単一行切断との重複と効果を分ける。

理論上の方向の参考：SCIP公式Doxygenのaggregation separator概要（Marchand/Wolsey, Aggregation and mixed integer rounding to solve MIPs, Operations Research49(3),2001,363–371の紹介） https://scipopt.org/scip/doc-9.0.1/html/sepa__aggregation_8c.php 。検索結果と概要だけを読み、ソースコードの移植はしない。これはMIR全般を実装済みという主張ではなく、既存の保守的な整数丸めを集約行へ拡張する仮説である。

## 初期診断結果

固定開発18問の根LP点を、既存cut/heuristicを無効にした自作Rust LPから取得。全18点の元MPS Fraction制約・境界違反は絶対1e-6以内（整数性は根緩和なので要求しない）。初期dump挿入スクリプトは同じ式がテストにも存在してassertで止まり、初回buildは変更なしだった。check2/build2で診断コードを実際に挿入し収集した。

各点で緩和点に近い128の整数元行側を選び、共有変数のある2行を正整数結合し、単純和または逆符号係数のgcd相殺を試した。2行の同じ元行は組み合わせず、検査した128行からの単一丸め切断と重複するものを除外。全単一CG切断と非同値と証明したという主張ではない。

18問中fhnw-binpack4-4で10、timtab1で11の違反候補。保存証明を別Pythonコードが元MPSのFractionから合成/投影/床除算し直して全件一致。比較専用HiGHS連続LPで、fhnwは元/既存main16cut/+集約10cutすべて0、timtabは元28694/既存main0cut28694/+集約11cut52566。native解・重みをRustへ返さず、このLP値を自作ソルバーの結果として数えない。

この信号を根拠にRustへの候補生成・証明記録・独立検査を実装して自作LP/短期B&Bを比較する。初期はMIP_AGGREGATE_CUTS既定off。mainへ採用するかは自作LPと終了時指標を測ってから判断する。

## Rust試作の最初の測定

Rustに2行の正整数結合、gcdによる共有係数相殺、既存rounding_rowの整数床除算を実装した。証明に2元行・側・正整数重みを保存し、独立Python検査も元MPSから再合成する。MIP_AGGREGATE_CUTS既定false。全128二値モデルの256割当てを整数算術で全列挙、自由連続変数の相殺・上下側・破損証明を検査。初回toyの内部check許容差0は区間による境界検査に合わず失敗し、テストだけ1e-12へ訂正。製品許容差は変えず、全列挙の元実行可能性は内部interval guardに頼らず整数活動量から判定するよう強化した。183 Rustテスト成功、toyの元MPS GMP検査と7破損証明拒否も成功。

同一binary flag0/1の10秒18問：timtab1のみ下界28694→52566、他17問はstatus/primal/dual全て一致。主解悪化なし。timtab1 60秒も同じ下界改善で、両方主解未発見。fhnwは28集約cut等を入れたが下界0不変。timtabの集約処理約0.00186秒/11cut。
