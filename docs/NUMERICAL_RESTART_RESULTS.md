# 数値失敗後のbest-bound再選択は不採用

同じ10/60秒、1thread・16GiBのgen-ip002でMIP_NUMERICAL_RESTART=0/1を比較した。ノードを保持した再選択は安全性テストに成功したが、主解を悪化させた。

| 秒 | 旧primal/dual | 新primal/dual |
|---|---|---|
| 10 | -4752.5026370 / -4840.5419613 | -4752.4773341 / -4838.1569910 |
| 60 | -4758.67403745 / -4840.5419613 | -4752.4773341 / -4837.0442913 |

下界は少し改善したが60秒でも主解が改善せず、主解・gapを悪化させた。60秒の最大openは46→389、最大RSSは3672→6752KiB。未証明領域は142→18へ減るが、探索領域が変わった効果でありLPの数値安定性を改善したとは扱わない。statusは両方numerical_error/time_limitのまま。限定した予算で採用根拠がないため、機能追加をmainへマージしない。

168Rustテスト、2700合成MILP/300根LP/32数値回帰に成功。全3探索方式での再選択によるノード重複/欠損とmin bound、再選択後の子の優先順を確認した。保存4点の元MPS/GMP・公式・根/カット検査は有効。数値回帰の変換未解決14例は保持する。同じgen-ip002の反復を独立した問題数に加算しない。

nativeの同条件10/60秒はPR47の記録を参照し、依然主解/下界とも本実装より強い。次はLP不能証明が取れない原因を元のboxと乗数から分析し、既存の区間推論をノードの有限boundsで強められるか検証する。
