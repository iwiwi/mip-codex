# 短時間で全頂点へ届くクリーク候補生成

2026-11-15 22:30 UTC、PR56/source core3125227aを凍結比較基準とする。現在のfractional coverは最大0.5秒の1/4を構成に使う。極大クリーク列挙を先にするとsorrell3で20000候補上限へ達し、後半頂点を覆う候補が少ない。先にgreedyをすると、候補内次数最大を毎段計算するため時間が足りなかった。

仮説：各頂点から立ったbitの先頭を選ぶ安価なmaximal化を先に行い、全頂点に最低1つの拡張候補を作る。その後に既存の予算付き列挙と彩色クラス拡張を行う。入力名/既知値による例外・nativeの解/重みを使わない。証明の整数被覆/全組対検査はPR56と同じで、上界の安全性は変わらない。

評価はsorrell3開発、sorrell7探索（Benchmark v2外）の15/60秒、全列挙検査、元MPS独立検証。改善しない場合もブランチと原データを保持し、改善なら固定18問と最終設定を再検査。既存のフルnative評価は変更しない。

## 初版と候補数制限

初版15秒はsorrell7 193/242、sorrell3 16/24で凍結PR56と同じ。sorrell3の根上界31も改善せず、20000候補に対するheap更新で約1726反復に留まる。1200 CLI/7410破損拒否成功。全頂点の安価なmaximal化だけでは上積みがない。

次版では候補上限を頂点数の4倍（下限64、上限20000）にして反復へ時間を回す。sorrell7では上限8192なので全4072極大クリーク等を保持でき、sorrell3では4096で打ち切る。これは全入力共通の頂点数規則で名前による例外ではない。初版ソースはartifacts/balanced-cliques-first-sourceに保持する。

4*n制限でも15秒sorrell3の根上界31、最終16/24は不変。4096候補で19760反復へ増えたが改善なし。sorrell7も193/242で不変。1200 CLI/7410破損拒否成功。候補の質と価格法のどちらがボトルネックか分けるため、create-new限定の診断dumpでRust候補を保存し、元pair制約で全組対を検査してから比較専用native被覆LPを解く。dump有効測定は性能比較に用いず、native重みはRustへ戻さない。

比較専用native LPで、Rustの4*n候補4096個（全組対を元pair制約から検査済）の最適被覆値は31.0だった。したがって価格法の反復不足ではなく候補自体が根上界31を改善できない。サイズ9..59。診断で出た主解は元MPSのGMP/公式で有効。

recognizeは競合次数の昇順に内部頂点を並べるため、先頭bit選択は低次数へ偏っていた。次版は末尾bit（高い大域競合次数）を選んで安価に大きいクリークを作る。動的な候補内次数の全走査はせず、整数証明とcandidate capは維持する。

高い大域次数の末尾bit版も15秒両問題の主指標不変、1200 CLI/7410破損拒否成功。次は各段階で高次数側の最大16候補だけ現在の候補内次数を調べる。全走査の費用を抑えて動的次数の効果を残す。これも上積みがなければ、予算で途中終了しても未被覆頂点を優先するseed順序と完全な動的次数を最後に診断し、改善しなければ本branchを不採用として残す。

16候補動的次数版はsorrell3の根上界31→30だが15秒終了時16/24は不変。比較専用LPは30.1037351108（4096候補、サイズ9..72）、60秒配分/0節点の独自整数被覆も30。候補の被覆品質は動的全走査版の比較診断23.00に届かない。診断点は元MPS検査へ回し、正式性能比較に混ぜない。

最後の案は全候補の動的次数をbit単位で走査（元の0..n走査を避ける）し、既に作った拡張クリークで覆われる回数が少ない未seed頂点を先に選ぶ。時間内に全頂点のseedを処理できなくても、良質なクリークの被覆が偏りにくいことを狙う。安全性は整数証明に依存し続ける。
