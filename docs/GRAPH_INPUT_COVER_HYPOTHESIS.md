# 元packing行を使う整数証明付き分数被覆

既存recognizeの厳密なrow_vertices条件を満たす入力行は、競合グラフのクリークである。各行から得たサイズ3以上のクリークを、列挙より先に候補poolへ入れる。元の色クラスは全頂点被覆用に維持する。追加行候補を一回ずつ使った整数被覆が全頂点を覆う場合、そのfloor(total/minimum)が既存彩色より強ければ初期countsに採用する。以後の価格付けと独立整数証明は従来どおり。列挙上限20000、構築1/4、全体2%最大0.5秒、メモリ制限を変更しない。

入力構造調査: cod105はサイズ56のpacking行1024本を持つが既存候補が直接保持していない。対してsorrell3/7は全行サイズ2である。問題名やサイズ56等の定数は実装判断に使わない。元行の再利用が汎用的に強い被覆証明と時間改善を生むか測る。既定無効MIP_GRAPH_INPUT_COVER。
