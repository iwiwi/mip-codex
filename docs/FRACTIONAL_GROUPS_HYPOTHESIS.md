# 列挙打切り後の分数被覆候補補充

既存の二値一様目的 packing グラフで、極大クリーク列挙が20000候補に達すると後半頂点からの候補生成が抑制される。元の候補をすべて保持し、各頂点から既存の共通近傍最大化による grow を追加する。追加上限は頂点数、メモリ検査と構築期限は維持する。証明は従来の整数回数による被覆検査だけを利用する。

私的根上界プロファイルでは、単純な低次数順/高次数順追加はいずれも12件で改善なし。列挙後に動的 grow を追加するV3は sorrell3 の2秒/10秒で根上界31→23、0.5秒では改善なし。sorrell7（240件の外）は改善なし。V3全12出力で元MPSの厳密Fraction証明と零解GMP検査成功、改変証明40件を拒否。これは根上界のみの測定で、探索全体の改善や最適性証明ではない。

本体候補は MIP_GRAPH_FRACTIONAL_GROUPS=0/1、既定0。有効時には分数被覆時間を従来の総時間2%・最大0.5秒から10%・最大3秒に変更し、候補補充に必要な時間を与える。この増加による探索損失を同じ実行ファイルの交互比較で測る。公開既存APIは旧動作を維持する。採用前に全Rust検査、生成小規模グラフ、開発188件、元問題の独立証明/GMP検査を実施する。問題名や既知解は最適化に使用しない。
