# 整数LP変数の一括固定をしない潜り探索

既存の根LP潜りは、選んだ分数変数で分枝する前に、その時点ですでに整数の全変数も固定する。速く狭い近傍を探すが、LP上で0だった整数変数を後で1へ動かす必要がある場合、すべての整数解を失う。

小さい反例: x,y二値、min x、x+y>=.5、y-x<=.5。根LPはx=0,y=.5。x=0も固定するとyの両分枝が実行不能。固定せずyだけを分枝すれば、次にxを1へ動かして整数解を得られる。min/max両方で元行/境界へ戻した回帰を追加し、node_limit/親bound不変を検査した。

`MIP_DIVE_FIX_INTEGRAL=1`で既存方式、`0`では選んだ分数変数の分枝だけを保持する。初期既定1。追加で固定した変数数を統計へ記録する。制限や反対分枝を一度試す手順は変えない。主解探索専用、局所bound/infeasibleをグローバルへ使わない。

強分枝の実験とは別worktree/branchで実装する。releaseの同時測定中はdebugテストだけ行い、binaryを上書きしない。強分枝の採用版へrebase後、18問の1/0比較、小/二値/中規模の独立照合で判断する。利益がなければ見送り、失敗も保持する。

## 結果と棄却

初回に作業ツリーの独立checker配置を忘れ、1657個の返却optimal点のGMP検査が未完了になった。失敗ログを保存し、checkerを配置して開始前の存在検査を追加。初回18問の28点も追加監査で全有効だが、判断にはchecker配置後の再測定を用いる。

source d2e5cb56の訂正18問 (115136/115137、8×5秒+10×2秒、1thread/16GiB、CPU0/1) は主解1改善/1悪化/16同等。pk1の20と19.999999999999993は丸め誤差で同等。bpp69→67は改善したが、binkar6794.860025→7429.760014へ悪化した。潜りLP数はpk15→55、markshare7→30、30n23→59、50v52→256など多くで増えた。既定は変更せず、本機能をmainへ採用しない。小1000/二値1000/中規模200の再検証は失敗0、139 Rust回帰も成功。

小反例の利益は実問題へ一律には移らなかった。bppでは初期修復seedを残したRINSの近傍が、潜りで改善したseedの近傍より良い解を見つけた（固定版のRINS固定数1400、非固定版1399）。潜り自身は非固定版で時間制限/候補0だったため、改善は直接の潜り成功ではない。単純な一括固定解除で採用を判断しない。

測定前にcheckerを必須化する変更は独立してmainへ反映する。稼働baseline snapshotは変更しない。
