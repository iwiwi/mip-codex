# 元十進境界と整数格子の安全性

親main PR116/FP30859e006f1e0445。冷dual候補を微小境界で検査した際、旧mainも4種類の誤った最適値を返した。x∈Z, −2≤x≤0, x≤−1e−16, min−xは真の最適値1だが、変数shiftが微小RHSを失い0を最適とした。x≥1e−16の負下端、上端0.9999999999999999、2変数の負側でも再現。ColdDual両flagで同じであり、冷dualは未採用のまま止める。

元MPSの十進tokenからBigIntでfloor/ceilを計算する。整数変数の有限境界と、宣言整数変数だけの正確な整数係数行を、整数実行可能集合を変えず整数格子へ丸める。絶対値2^52以下の正確な整数境界だけを扱い、それを超える値や利用できない情報を推測しない。RANGESは元十進数の和と符号を使う。元Modelをcloneし、元変数/行index・目的を変えず、処理時間を全予算へ課す。通常の整数RHS/0–1境界はmetadataもcloneも不要。

変数/行indexと変更境界のbinary64 bitを型付き証明に残す。Python検証器は元MPSをFractionで独立に読み、宣言整数性・整数係数・厳密ceil/floor・順序/重複/有限値/schemaを許容幅なしで照合する。その変換を他のカット/目的格子/箱/原行master証明より先に適用し、キャッシュされた元MPSを変更しない。元点のGMP絶対誤差1e−6、目的相対1e−8と親masterの厳密下界検証を維持する。
