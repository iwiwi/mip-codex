# 重み付き頂点被覆による独立集合の主解探索

汎用binary packing認識の後、競合グラフの頂点被覆の補集合を独立集合として探索する。辺の重み、2段階の除去/追加、近傍変更による再追加制御、古い重みの減衰を独自Rustで実装した。方法の出典はGRAPH_WEIGHTED_COVER_PLAN.md。既存最適化コードはコピー/委譲していない。新しい点はcompatible graph上の全組対検査を通った場合だけ採用し、上界や枝刈り条件は変更しない。

元の局所探索に20%、被覆探索に残りを配分する。既定の128*n/500000交換の範囲で改善した場合だけ1024*n/2000000交換まで伸ばし、全体では制限時間の5%かつ最大3秒に限る。改善が無ければ元の回数上限で止まる。MIP_GRAPH_COVER_LOCAL=0/1、最終版は既定有効。問題名/既知解/目標値を実装に埋め込まない。

sorrell7はBenchmark v2外の探索用入力であり、240問の成績には加えない。最終版で15秒追加3回とも-193、60秒追加2回とも-197。最適性は未証明で、既存の公開最良値-198を超えていない。主解品質は改善したが、下界は改善していない。

sorrell3は同じ6042153節点で最適宣言。同CPU7の3組比較で元18.45797/18.44847/18.43111秒、新18.91649/18.88895/18.91975秒、中央値18.44847→18.91649秒で約2.5%遅い。局所探索の追加約0.52秒が代償となるため、速度改善とは主張しない。固定開発18問の主解/下界/statusは全て直前版と一致した。

比較可能な同資源sorrell7のnative60秒（PR38の既存データを再掲、今回は再実行なし）：HiGHS主解-186/下界-231、SCIP-152/-583.148246391059、GLPK-21/-479。全点GMP/公式検査有効。Rustの主解は良い一方、HiGHSの下界は依然本実装より強い。全Benchmarkで商用相当性能を達成したとは主張しない。

## 検証と不採用案

180 Rustテスト成功。100グラフ×300操作の各段階でスコア/未被覆辺集合/位置表/重み和を再計算し照合、96小グラフで全列挙の最適値を超えないことと点の組対検査を確認。CLI200モデル×6制限=1200回、破損証明7200件を拒否、2700合成MILP/300根LP/32数値例/8preflightも成功。

初期の16*nで改善しなければ打切る案は、60秒配分/0探索節点の診断でsorrell7を-191で止め、初期方式-195より悪化したため不採用。成功した場合だけ探索を延長する方式は、2秒枠の診断で-197を得た。15秒まで局所探索を許した長時間設定/0節点診断でも-197のままで追加改善がなく、最終は最大3秒へ戻した。これらは本探索60秒の結果と区別して保存する。

最初のsmokeはBenchmark v2外のsorrell7を通常manifestで検索してKeyErrorになり、sorrell3の部分結果だけが残った。専用スクリプトへ切替えて再測定し、部分結果も別に再検査した。最初のCLI全列挙は出力先を指定し忘れ、既定ディレクトリへ出力したため、その時点の結果を一意のarchiveへコピーし、一意の出力先で再実行した。旧試行は各既存evaluation archiveに保存済み。

新しいRust子モジュールも収集するため、snapshotコピーとsmokeのsource SHA収集を再帰化した。作成したsnapshotのsource FNVが実行バイナリと一致し、子モジュールが存在することを確認。進行中のnative全件比較は凍結した旧コードのままで変更していない。

独立再検査は保存64点すべてGMP/公式で有効、74記録/134切断が有効。うち38記録はgraph認識/彩色/残存上界の独立メタデータ検査も有効。反復を独立問題とは数えず、探索木の全再生をしたとも主張しない。原データgraph-cover-evaluation。全240問Rust snapshotはcreate-only、source fd6bfe6a、receipt experiments/graph-cover-snapshot-20261115.json。

次は重なりを許す分数クリーク被覆による上界を検討する。比較用LPの診断で小さい値が得られたが、そのnativeの重み/解はRust最適化へ渡さず、独自Rustで候補を生成し、整数被覆の証明として独立検証できる形を調べる。
