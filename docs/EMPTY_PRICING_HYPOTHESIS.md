# 幅広いLPで厳密なゼロ空列の価格付けを省く

main PR113を親とする独立研究。係数が一つもなく、現在の目的係数も厳密に0の列は、任意の双対乗数に対し縮約費用が厳密に0で入り変数にならない。列自体/変数復元/境界/基底対応は保持し、primal pricingの走査候補からだけ省く。Phase I/Phase IIの目的ごとに候補を作り直すので、空でも非零費用（微小値を含む）の列は必ず残す。全最適性/不能/非有界の検査と許容幅を変えない。

MIP_LP_EMPTY_PRICINGは研究で既定無効。小LPへのオーバーヘッドを避け、内部列数1024以上かつ半分以上がゼロ空列の場合だけ昇順index集合を使う。元index順のtieとdegenerate時の最初の候補を保持する。cost変更/行追加/LP再構築ごとに再計算し、親の列や基底を変異させない。dual simplexの候補走査にはまだ適用しない。

3追加検査は1300変数のゼロ空列を持つLPで点/基底/pivot/flip/証明が旧版と完全一致、非零空列の有限bound flipと微小非有界目的を維持、cost0→非零/空列への行追加で候補を再構築することを確認した。最初の実装はclosureのself借用中の統計代入でコンパイルエラーになり、代入を走査前へ移して修正したログも保持する。

map等の原行部分LPは原変数16万に対し有効行数数千で、空列が多いと推定した。3開発問題の10秒flag対照で実際のskips/callsと品質/仕事量を測る。まだ採用しない。資源制限根の実行可能性MIP（phase-two別branch、188評価中）とは別変更として検査する。

初期FPb9c77eea860c448fの10秒3問ではmap10下界−965.9456150849444→−765.0515247350392、savsched1 26.49999999997751→31.099999999958072、jarama279.9999999999938→285.9999999999931。主解は全てなし。省略カウンタ初版はdegenerate時の早期停止でも末尾まで数え、実省略数を過大にする可能性があったため、v2では停止indexより前だけを数える診断修正を行った。最適化の入り変数・計算結果は変えない。初版のカウンタは走査全体換算値で、厳密な実省略数とは解釈しない。
