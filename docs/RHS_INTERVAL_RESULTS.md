# 疎LPの片側RHSを保守的な区間へ変換する

## 問題と判断

従来の標準形変換は、変数shift後のRHS和の誤差が1e−9を超えるとNaNを返す。rd-rplusc-21は一部の誤差1.05〜1.54e−9により0pivotで数値終了していた。しきい値を上げず、元問題を包含する片側制約の別表現を導入する。

既定有効候補3dc80cbe0e / 9b884c5d9667c934を採用する。337テスト、全行の独立分数検査、生成MILPと開発188対の全点・証明検査を通過し、数値終了5→4と生成問題の最適判定7→103を確認した。MIPLIBでの主解改善・速度優位・新記録はない。

## 変換の根拠と制限

元係数A、binary64係数Â、shift t、向きs∈{−1,+1}に対し、変換後RHSは

`rhs >= s*b − s*Â*t + max_{x in original box} s*(Â−A)*x`

を満たす必要がある。実装は各係数の隣接f64までの誤差上界と元boxの最大絶対値を用い、RHS端点と全和を外向きに囲む。独立検査器は上の式を元MPSのFractionで直接検査する。元係数の大きさだけを理由に許容を広げていない。

適用は従来RHSが非有限となった片側行のみ。等式・有限rangeは対象外。元十進数ではSource署名一致を要求し、係数の不確かさを持つ変数に有限の元boxがなければ適用しない。元モデルから消えた非零項も拒否する。binary64で整数に見える小数係数もSourceで認識する。可変行や境界でSourceが不一致となれば適用しない。

LP後はmain122の元係数下界証明を維持する。未証明下界を使わず親下界で主解探索を続け、未証明葉では最適性を撤回する。主点は元問題で検査する。MIP_RHS_INTERVAL_FALLBACK=0/1で比較でき、既定は有効。診断dumpは通常無効、既定上限1024、全行検査時だけ100000に指定した。

- 最終候補337 Rust成功4ignored（main122の334件とRHSの3件）。
- rd-rplusc-21の全55193適用をFractionで許容なし検査。行ID・名前・向き・shiftの正確値・元boxを照合し全有効。dump SHAは3a20533da62f8996be7c264bf1082c55f6c6ad1674bd7d6a3709bbb61e47120c。非保守的RHS、非有限値、行/shift誤り等の10改ざんを全拒否。
- 固定大値と小数係数を持つ200 MILP、flag0/1計400出力。整数変数全列挙と連続変数の有理数端点から真の最適値/実行不能を求め、不正な下界・最適/実行不能判定0。最適7→103、数値終了193→91、真の実行不能6件を新たに証明。全290点GMP有効（前131/後159）、全436適用RHSも厳密検査有効。Decimal精度100でMPSに正確に書いた。
- 一般800/二値400出力は全列挙一致、実際の親下界証明1028件、改ざん拒否8224件、GMP1200点がすべて有効。
- 主点のGMPは行/境界/整数性を絶対1e−6、目的値を相対1e−8で検査。解析下界・親証明・RHS証拠に許容を加えていない。
