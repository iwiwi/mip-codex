# 根の強分枝に目的影響と実行不能hintを使う

強分枝の短い候補列を、分数度上位6とabs(元費用)×分数距離の上位2の和集合から最大8変数とする。最初の分数候補と目的候補を交互に試し、既存の候補の多様性を保つ。両子の自作warm LPは各256pivot、全体5%/最大.1秒という既存制限を維持する。

別の設定で、子LPの実行不能を選択hintとして使う。反対側が予算切れでもその変数を選択できる。元の候補へ戻したい場合は`MIP_STRONG_OBJECTIVE=0`、実行不能hintを無効にする場合は`MIP_STRONG_INFEASIBLE_HINT=0`。採用版の既定は両方1。強分枝自体を無効にする既存設定も保つ。

子LPのbound・主解・実行不能をmainへ書き戻さない。両子実行不能でも、親をそれだけで枝刈りせず、通常のmain探索が改めて処理する。成功したoptimal LPからの擬似コスト学習だけは従来どおり行う。候補index/選択indexを出力して選択の影響を確認できるようにした。

## 検証と結果

source d9e9c41、113501/113503で4設定を固定18開発問に対照した（8問各5秒＋10問各2秒、1thread/16GiB、CPU0/1）。全72run時間制限。主解18問は全設定同等。併用版だけ30n20b8の下界51→51.7547169811へ改善した。候補の元変数1が実際に選ばれ、mainの通常LP探索がより高い下界へ進んだ。新下界は通常float LPからの値で、追加の独立した厳密下界証明ではない。

返却56主解は原MPSのGMP絶対/公式とも有効、268cutと72目的構造証明もFractionで全有効。1000小/1000二値/200中規模のHiGHS・全列挙・原MPS検査は失敗0。Rust138回帰、80二値min/maxの全列挙を4設定へ広げた照合も成功。両子実行不能でもmain node_limit/親bound不変を明示検査した。

30nの60秒対照113850（CPU4、同資源）はclassic下界51/主解なし、併用下界51.7547169811/主解なし。主ノード486→330、LP549→390だが、同じ時間制限内の異なる探索なので速度改善とは扱わない。両runの60cutと構造証明は全有効。主解なしを隠さない。

PR19の二値1000と同じ固定入力の探索量は主ノード2703→2521、LP11954→11772。別時刻の単発なので時間合計の差を速度優位には使わない。全240件での優位は未達成。通常18問で悪化がなく、短期/60秒の両方で下界が改善したため両設定を採用する。
