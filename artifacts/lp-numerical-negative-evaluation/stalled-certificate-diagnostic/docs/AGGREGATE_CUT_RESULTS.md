# 二行集約からの厳密整数丸め切断

## 変更と証明

元MPSの整数係数・整数RHSの2行側を正整数の重みで合成する。共有係数の逆符号をgcdで相殺する重み、または両方1の単純和を候補にし、既存の整数床除算を適用する。非負整数変数以外の残項は元の有限な整数point境界で緩和し、相殺できず投影できない項があれば候補を捨てる。全演算はchecked i128、合成係数/RHSは絶対2^52以下に制限する。

元の2行・側・正整数重み・除数をJSONに保存。Rustは出力直前に元行から再合成して確認し、Python独立検査器も元MPSのFractionから合成・投影・床除算を再計算する。元行からだけ導出し、切断間の循環証明を作らない。浮動小数の根点と違反量は候補選択だけに使う。

近い128行側、各共有変数16行まで、4096行対、約100万係数処理を予算に、既存の根cut準備枠（総時間の5%、最大0.25秒、既定2round）内で実行する。既存の単一丸め・coverと同じPoolで既知切断を重複除去する。`MIP_AGGREGATE_CUTS=0/1`、最終既定true。丸め対象の非負整数変数がない入力は新しい準備処理を省く。入力名/既知値による例外はない。

## 測定結果

同一binaryのflag0/1、1thread/16GiB/10秒、固定開発18問。timtab1の下界だけが約28694→52566、残り17問のstatus/primal/dualは全て一致。主解の悪化はなかった。timtab1は60秒も同じ下界改善、どちらも主解未発見。11集約cut、生成・検査処理約0.00186秒。最終既定trueの追加10秒測定も52566を再現。

fhnw-binpack4-4は28集約cut等を追加したが終了時下界0/主解未発見のまま。節点数の増減だけを速度改善とは主張しない。厳密に合成した候補が追加できても、全問題で性能を改善するとは限らない。

## 検証と失敗の扱い

183 Rustテスト成功。自由連続変数の相殺と上下側、128個の8二値モデルの全256割当てを整数算術で照合し、全切断が元実行可能点を残すことを確認。toyのGMP/独立証明と7破損拒否、独立検査器8テスト（2側各8改変等）/preflight8テスト成功。

最初のtoyは境界点を内部の区間guardへ許容差0で渡して失敗。テスト側を1e-12へ訂正し、全列挙の元実行可能性判定は内部guardに頼らず整数活動量から計算するよう強化した。製品の許容差は変更していない。失敗ソースとログを保持。

集約有効の2700合成MILP/LP成功、最終適用guard・既定trueでも追加500合成成功。32数値/serialization例成功。根LP比較は新cutを無効にした400例（通常200/スケール100/単位変換100、単位変換はmainのRevised）で成功。初回の通常/スケール比較は新cutの無効化漏れで各1件、より強い整数下界を元連続LPと比較して失敗したため、比較scriptにも新flagを追加して条件を揃えた。

別途試したDenseの単位変換100例では50件のnumerical_error。保存した全50入力をPR56の凍結版と現在版に同じDense設定で与え、status/objective/dual_bound/nodesが全て一致した。既存Denseの失敗として元ログを残し、合格した400例と混ぜて隠さない。主要ベンチマークは既定Revisedを使う。

最終smokeの28点と根収集/toyの6点、計34点は元MPSのGMP/公式とも有効。46記録/222切断の導出も独立再検査有効（反復を含む）。別途32数値fixtureは専用GMP/Fraction検査で有効。これらを通常経路へ追加監査した最初の試行では、極大bound/costの4記録でHiGHS reader拒否、2記録で公式checkerのobjective行RHS parser assertion/abortがあった。これを解不正や公式合格へ付け替えず、失敗ログを保持して専用検査と区別する。独立検査は切断の数学的導出と実行可能点を対象とし、探索木全体の再生ではない。
