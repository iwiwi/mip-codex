# 大きい根LPの双対化適用範囲診断

main PR112を親とする独立研究。開発resource_limit11問を元MPS構造だけで集計し、ns1760995は原行615388・変数17956・nnz1854012、従来標準化概算1289MiB、双対概算200MiBだった。他10問も全て記録し、holdoutは見ない。概算は固定列/前処理/範囲分割を省く診断で、正確なメモリ保証ではない。

既存dual_formの変数数上限10000を20000へ変えた研究binaryで、明示的な既存workspace設定2048MiBを両側同一に指定し、root双対off/onを対照する。製品既定512MiBや監査許容幅は変更しない。これは単純なcap増加の採用提案ではなく、より小さい双対基底に性能信号があるかの事前診断。旧LPでの一律2GiB増加の負結果も取り消さない。成功時の元LP primal/dual検査と絶対gap1e-9、同deadline/残pivot fallbackは維持する。

信号が出た場合だけ、algorithm-specificな512MiB admissionとdual失敗時に巨大primalへ戻らない明示状態を別実装する。元問題の不能/非有界をdual状態だけから宣言してはならない。改善しなければ拡大適用は未採用とする。

事前対照FP3ddd9df8ca8a11d3のns1760995×60秒は両側time_limit、主解・下界なし。primal3550pivots、dual有効側4198pivotsだが、双対1attempt/0success/1fallbackで終了。進んだpivot数を品質改善扱いしない。既定の上限拡大やDualOnly admissionは実装・採用しない。生出力と独立証明検査を保全する。

次はmainの上限へ戻して制約生成を独立exampleで診断する。最初に箱点が違反する原行から最大512行を追加し、全変数を連続緩和した部分モデルの最適点を全原行で走査、追加違反行があれば次のmasterへ足す。元モデルを変更しない。master不能/非有界/数値停止は単なる診断停止で元の状態へ変換しない。元全行を満たす点もLP診断点としてのみ保存し、MILP最適性/整数実行可能性の宣言には使わない。初回exampleは存在しない統計field lp_statsのコンパイルエラーを保全し、lp_solvesへ修正後に実行した。
