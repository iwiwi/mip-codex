# 次の診断仮説：複数の元行から二値clique切断を作る

現在の一般MILP向けcoverは、各元行から単独のcoverを作る。別々の元行が二値literal同士の排他関係を与える場合、排他関係を合成したclique（すべての対が同時に1になれない集合）についてliteral和≤1を追加できる。3つのpair不等式から三角形の和≤1を得るような場合は、個々のpairより強い。

まずコードを入れず、保存済み開発側の根点だけで候補を診断する。元行の一方の側を選び、二値以外の項を元の有限境界で緩和し、負の二値係数は1−xへ置き換える。2項の重み和が容量を厳密に超える場合だけ、元行・側・2変数・literal符号を排他証拠にする。生成されたcliqueの全対に元行の証拠を必要とし、切断の係数/右辺をliteral集合から再計算する。元境界しか使わず、子節点の局所fixingを全体cutへ混ぜない。

候補選択は時間/仕事/メモリを制限し、同じ変数の正負literalを1つのcliqueへ入れない。Fractionで全pair証拠を再計算し、保存根点で違反する候補があるか、LP下界が強まるかを調べる。ネイティブLPは比較だけで、重みや点をRustへ返さない。候補がなければ先に実装せず、結果を保存する。

採用するならProofに元pair証拠を追加し、Rust側と独立Python側の両方で検証する。二値小モデルの全列挙、符号・範囲行・非二値投影、証拠改変の棄却、固定18問、保存点のGMP検査を必要とする。既存の特殊なuniform binary graphの上界証明とは別で、一般MILPのLPへ有効不等式を追加する機能である。
