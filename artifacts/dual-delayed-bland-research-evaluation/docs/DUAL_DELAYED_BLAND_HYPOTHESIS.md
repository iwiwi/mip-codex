# warm dualの退化直後の行順位

通常warm dualは双対ステップbeta<1e−10を一度観測すると、次の行選択から直ちに最小基底変数番号へ切り替える。最大違反行をさらに短期間選ぶ方が良い可能性を検証する。連続退化25回を超えた場合に既存のBland側順位へ切り替え、25は既存primalの連続退化切替と同じ共通定数とする。モデル名や既知値を条件にしない。

RESTORATION=trueのゼロ目的回復dualは既存の即時切替を維持する。候補のdual適格性、ratio test、bound flip、factor更新、元点/dual証明、数値許容誤差、連続退化500/構造依存dual pivot cap/総pivot/時間上限は変更しない。順位変更のみであり、Devex/steepest-edgeの実装とは主張しない。

採用済みmain fcda1f65b/FP12ee05629152fe08を基点に、別worktree/branch dual-delayed-blandで試作。時間予算案とは独立させる。既存全Rustを実行後、ソース/ELFを固定し、pk1/mad/markshare_4_0/SP97など開発モデルの10秒対照を行う。改善シグナルがなければ不採用資料として残す。シグナルがあれば元MPS独立検査とLP oracle/188対の必要な検証へ進める。

試作FPb7ce207f6c72d105は既存240 Rustに成功し、親FP12ee05629152fe08と両方のソース/ELF/SHAを実行前固定。初期10秒はpk1 17→約20、mad 0.3766→0.424と主解が悪化した。madはノード28702→39077/pivot707391→540240だが、探索量やpivot減だけを改善と扱わない。採用候補から外し、残りの選択結果と元MPS監査を保存する。全188/大規模LP oracleへ広げない。

最初のdriverは5番目のNiddaをnidda.mps.gzと誤指定した。最初の4有効モデル対を保持し、正しいneos-3754480-nidda.mps.gzを別のCPU45対照で実行した。元driverの失敗ログ・入力訂正記録を保存し、4対完了を全5対正常完了とは記さない。修正driverには全名前のmanifest/development事前検査を加えた。

最終選択は主解1改善2悪化2同値、下界は全5件同値。Niddaは13590.827113447798→13125.13685791022（両版numerical_error、下界−1216923.270104406）、markshare_4_0は約1、SP97は884197292.16で同値。全10点・10証明が元MPSのGMP絶対・公式検査で有効だった。Nidda改善も除外せず記録するが、2主解悪化のため不採用で確定する。主ソルバーへこの行順位変更を入れない。
