# 根固定列のLP省略

元十進境界から証明できる根固定変数だけを省く。子節点での固定は列構造を変えず、warm basis互換性を維持する。元モデル・復元された解・目的計算・独立検査の対象は変えない。非整数FX 0.3のように元境界の同一性が証明できない場合は省かない。

## 検証

明示有効でRust152テスト、合成2700、根LP300、桁落ち22例、大整数10解が成功。固定18問のprimal/dual/statusは変更前後で同一。保存28解と140cuts（38証明記録）はGMP絶対検査/公式検査/Fraction証明検査ですべて有効。gen-ip002の未証明LP実行不能によるnumerical_errorは引き続き残し、解決したとはしない。

## 性能と採用

30n20b8では7282列を省ける。ヒューリスティック/strong/coverを切り同じCPU16で交互に3回測定した。根1節点の内部時間中央値は0.088172994→0.075788761秒。50節点/50LP、下界51・主解なしという同じ結果までの中央値は5.064074891→4.139779938秒（約18%短縮）。外部wallは独立に保存し、この数値は内部時間。

標準設定10秒では30n20b8が48→57節点、同じ下界51.75471698112993・主解なし。mcschedの14列、timtab1の13列、bppc4-08の1列も省くが、ここでは一般的な高速化の証拠として扱わない。対象列ゼロのmarkshareは同じ1,486,619節点/1,494,216LP、35.642062561→35.683000246秒でほぼ同等。全体の解けた問題数やnative超過は主張しない。

この限定的だが再現した改善に基づき既定で有効にする。MIP_FIXED_COLUMNS=0で無効化可能。適格列ゼロなら各節点の適格性検査を行わない。

最初の10問コマンドで存在しないneos-1126860/bppc8-02を誤記し、両側ともn5-3の後KeyErrorで停止した。失敗runも保存し、既定の正しいmc11/bppc4-08を用いた10問を再測定した。比較判断には正しい固定18問だけを使った。

生データと元パス/hash台帳はartifacts/fixed-columns-evaluation。主実験は既定無効版に明示フラグを指定し、その後既定有効に変更してRust検査を再実行する。
