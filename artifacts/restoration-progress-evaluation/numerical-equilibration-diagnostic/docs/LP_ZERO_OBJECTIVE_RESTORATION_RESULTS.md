# 目的0の双対法で、実行不能な基底からLP探索を再開

再分解・厳密残差補正の後も比率検定が失敗する場合だけ、既存の有界双対法へ目的0を渡して基底の実行可能性を回復し、元目的の主単体法へ戻す。変数境界や係数を変えず、値をclipしない。目的0の双対値を元目的の下界として使わない。

1探索state最大4回、既存の総pivot/時間/dual pivot capを共有。補助目的では双対ステップが常に0なので500回の双対退化停止を適用しないが、通常dualは従来通り。不能を返せるのは人工変数が全固定0の場合だけで、通常の元Problem/元MPS矛盾検査を通ることを必須とする。通常/補助をconst genericで別単体化し、通常経路に実行時モード引数を入れない。

## 副作用の切り分け

初回の実行時bool共有版は、binkarの10秒主解7069.300014→7093.730005へ悪化。新回復は呼出0回だったが同CPUの3組で再現した。const genericで別単体化すると、同CPU3組のbefore/after全て7069.300014、下界6646.232386090788、after2181節点となり副作用が消えた。固定18問も最終版は全status/primal/dual一致。コード生成の詳細原因を断定せず、旧版と全ログを保存する。

9根の10秒診断では新点なし。60秒では上記neosだけ新点を得た。uccase9は4回回復後に上限で停止、unitcal_7は時間切れ。回復回数やpivot増加だけを進捗とは数えない。

## 検証

最終188 Rust単体成功。境界外基底から正しい最適点へ進む例、真の不能と矛盾、期限切れ、600独立行を600pivotで回復する例を含む。2700合成/400根LP/32数値例を最終コードで再実行して成功。checker8/preflight8も成功。

失敗版・繰返しを含む45保存整数点は元MPSのGMP/公式とも有効、61記録466切断の導出も有効。反復を独立問題と数えず、探索木の全再生をしたとも主張しない。LP点の検査と整数点の検査を区別する。
