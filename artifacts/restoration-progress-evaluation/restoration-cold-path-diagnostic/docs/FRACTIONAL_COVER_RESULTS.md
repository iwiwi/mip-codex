# 整数回数による分数クリーク被覆上界

## 変更と証明

認識済みの一様目的二値競合グラフで、重なりを許す競合クリークの被覆から上界を求める。既存彩色クラスを初期被覆として保存し、時間・メモリ・個数・深さを制限した独自の極大クリーク列挙とgreedy拡張で候補を生成する。列挙未完でも安全であり、列挙完了を最適性の根拠にしない。

頂点価格の和が大きいクリークを選び、その頂点価格をexp(-1)倍する独自ヒューリスティックをlazy heapで実行する。既存最適化ライブラリへ委譲せず、native LPの重みや解も使わない。生成時間は総時間枠の2%、最大0.5秒、その1/4をクリーク構成に割り当てる。最大20000クリーク、最大500000反復。入力名による例外はない。

クリークCの正整数選択回数をc_C、総数をT、全頂点の最小被覆回数をk>0とする。独立集合Sではk|S|≤Σ_C c_C|C∩S|≤Tなので、|S|≤floor(T/k)。価格の浮動小数値は証明に使わない。最終クリークの全組対と整数被覆を再検査し、既存彩色より小さく既存主解以上の場合だけ採用する。

各探索接頭辞Pでも、Pに交わるクリークだけの重み和T_PとP上の最小被覆k_Pでfloor(T_P/k_P)を得る。彩色接頭辞上界とのminを使う。JSONに元変数番号のクリークと回数を保存し、独立検査器は元MPSから競合辺・被覆・上界を再計算する。探索木の全分枝の独立再生は行わない。

## 検証

5頂点の全1024グラフで、整数被覆と全接頭辞に対する全実行可能部分集合の上界を全列挙照合。極大クリーク集合も全列挙と一致し、重複頂点・非クリーク・未被覆・重複順序の不正入力を拒否する。最終既定有効版の181 Rustテスト成功。最終構成順序のCLI200モデル×6制限=1200件成功、破損証明7410件を拒否（初版も別途同数成功）。固定開発18問はstatus/primal/dualが全て直前版と一致。最終既定有効版の1200 CLI/7410破損拒否も成功。最終版追加15秒1回で193/242、60秒2回で197/241を再現。

全240問用snapshotはcreate-only、source core `3125227a`。再帰source fingerprintとbinaryの一致を確認し、受領票は`experiments/fractional-cover-snapshot-20261115.json`。進行中のnative全件比較の設定・snapshotを変更せず、Rust全件評価もまだ開始しない。

原データは`artifacts/fractional-cover-evaluation`。計画・比較用LP診断・不採用初版は`FRACTIONAL_COVER_HYPOTHESIS.md`を参照。

保存点の一括再検査ではcustom19点と固定開発13点の計32点がGMP/公式とも有効、19件のグラフメタデータ証明と固定開発18記録/67切断も有効。反復を独立問題と数えず、探索木の全分枝を独立再生したとは主張しない。各原データのSHAをrelocation-ledgerに保存する。
