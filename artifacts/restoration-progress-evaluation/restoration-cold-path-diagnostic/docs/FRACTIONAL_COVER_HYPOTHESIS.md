# 分数クリーク被覆による厳密な整数上界

2026-11-15。sorrell7の元pair制約LPは0.5の点を許すため、そのままの根LPでは彩色上界379を改善できない。競合クリークを増やした比較用LPでは、greedyに拡張した1311クリークで281.923、全4072極大クリークで237.4となった。後者の列挙はPython約0.31秒、比較HiGHS約2秒。自作Rust LPで前者を解くと約25.4秒/29632pivotで同じ値（途中で別の診断とCPU6が重なったため時間は正式比較ではない）。これらは診断であり、nativeの重みはRust最適化へ渡さない。

より単純な独自候補生成：頂点の被覆回数が少ないほど大きい価格を持たせ、価格和が最大のクリークを繰り返し選ぶ。選択回数を整数c_C、総数T、各頂点の被覆回数の最小をk>0とすると、任意の独立集合Sについてk*|S|<=sum_C c_C*|S∩C|<=Tなので|S|<=floor(T/k)。点/価格の浮動小数計算を信用せず、最後はクリークの全組対と整数被覆だけで検査できる。

NumPyの汎用加算のみを使った予備診断で約2秒/29000回、価格減衰exp(-1)なら整数上界244、exp(-0.3)なら251。これはまだメインへ使用しない。独自Rustでは単調に減る価格の和をlazy heapで管理し、候補の生成を高速化する。各prefixに対して有効なクリーク重みの和と被覆最小値を計算すれば、既存の根prefix彩色上界とminを取れる。最終proofは元MPSから独立検証する。

診断手順の失敗：native getterが配列を複写する箇所をループ内で繰り返し呼び、遅い比較スクリプトを停止した。元ソース/終了状態を保持し、配列を一度だけキャッシュして再実行した。正式ベンチマークや進行中の凍結snapshotには変更していない。
