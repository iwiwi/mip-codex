# 行・列の単位と元データでの検査

2026-11-15、source4bff42c。問題名による条件分岐はなく、行列の係数から同じ規則を適用する。LP最適化は引き続きRust実装で行う。

## 再現した誤判定

`min -x, 1e-12*x<=1, x>=0` の最適値は-1e12だが、旧revisedは小さな係数をpivot閾値で無視し、unbounded_relaxationとした。列正規化で解消した一方、`x-z<=0` を加えると列の最大係数は1になり誤判定が残った。列の正規化後に小さい行も正規化して、両方をoptimal -1e12へ訂正した。返却点は元MPSのGMP絶対検査に合格。

`x<=z, (1+2^-40)*z-x<=1` も有限な最適値-2^40を持つ。無限stepを宣言する前に非ゼロの小pivotで比率検定を再試行し、元データでrayを検査する。両エンジンがこの例を解く回帰を追加。MPSには係数の正確な十進展開を保存し、GMP検査も通過した。

## 変換と復元

正の2の冪s/rを使い、`x'_j=s_j*x_j`、`A'_ij=A_ij/(s_j*r_i)`、`b'_i=b_i/r_i`、`c'_j=c_j/s_j`、`u'_j=s_j*u_j` とする。列の最大係数絶対値が[1e-4,1e4]外なら列単位を正規化し、その後に小さい行を正規化する。slack幅もrで割る。表現できる範囲では二進データを正確に変換でき、各係数/目的/幅/RHSの往復一致を確認する。underflowや有限値のoverflowを黙って0/無限大へ変えない。変換できなければnumerical_errorとする。

返却点/rayはsで割り、行乗数はrで割り戻す。元Problemで主点・境界・行・目的・dualを再検査し、Model側のshift定数を二重に加えない。warm basisとLU/etaは変換後の単位で保持し、原係数から決める単位はbounds変更で変えない。元単位の検査が通らない候補は最適/実行不能として採用しない。

## 実行不能・非有界の候補

infeasible候補は、行乗数と全box/slack幅から元Problemで矛盾を確認する。積和を外向きに丸めて下限/上限を計算し、無限幅の列の符号がゼロをまたぐ場合は整数で正確な符号を確認する。反対向きの乗数も試す。確認できない場合はnumerical_error。

有限f64を整数mantissa×2の冪へ分解し、各積をu128、正/負をそれぞれ68語の整数配列へ累算する。全指数域の積と64-bit個数のcarryを保持できる4352bitを確保し、浮動小数点の積のunderflow/overflowや相殺に依存しない。Python Fractionで独立生成した501fixtureと比較した。最大値の積2000個の相殺と最小subnormalの積が残る場合も含む。

非有界候補は元の基点の数値実行可能性に加え、非負方向、有限上限の列が動かないこと、元行の方向と目的改善の符号を確認する。行/目的の符号は整数積和で検査する。これは元Problemのf64数値に対する検査であり、元MPSの十進係数による厳密有理数最適性証明を実装したという主張ではない。元MPSへの主解GMP検査を別に継続する。

## 密表参照版と未解決の範囲

密表にも二進単位を使い、元行列からbasisを作り直してGauss-Jordan更新の蓄積誤差を減らす。人工変数のゼロ残差処理を既存のFEASと揃え、元の非負/単一変数上限へ点を戻して全行/dualを再検査する。再構築にも期限を適用し、作業用コピーをメモリ見積りへ含める。

極端な単位変更100問では、疎版は100問成功したが、密表は最終50問numerical_errorが残る。未解決として保持し、成功件数へ混ぜない。試作は失敗83→79→71→50と減少。共通RHS単位の追加正規化は79へ悪化したため棄却した。過去の通常200問・行/目的scaled100問は両エンジンで通過した。

## 独立検査器

正確な十進展開が32文字を超える係数で旧GMP checkerがassertしたため、その結果は未検証とした。MIPLIB_ABSOLUTE版だけ数値入出力を可変長にし、D指数も扱う。検査器の許容誤差は変更しない。通常版と稼働baseline snapshotは変更しない。

Python診断側の行境界vector propertyはpybindで毎回listへ変換されるため、行ごとの取得はO(m^2)になっていた。境界を一度だけ取得し、元のPython float/bool型のまま使用する。NumPy配列にした試作では不合格点のboolがJSON化できず停止したため、型を保つ版へ修正し不合格結果のJSON化も回帰検査する。旧監査の部分結果・停止理由・型エラーを保存し、新しい監査を別ディレクトリで実行した。
