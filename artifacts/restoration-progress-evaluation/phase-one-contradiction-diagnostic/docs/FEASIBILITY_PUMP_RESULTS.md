# 初回主解を探すbinary feasibility pump

根LPの整数変数がbinaryまたは元境界で固定の場合、整数への丸めと丸め点への距離を最小にする自作Rust LPを交互に実行する。連続変数は距離に含めず、行列/境界を変えないcost changeのwarm基底を利用する。循環時には分数性と固定seedによる順位で小さい反転集合を作る。最大64 LP、各4096ピボット、時間の10%かつ最大1秒。出典と独自実装の範囲はFEASIBILITY_PUMP_PLAN.mdに記載した。

変更した目的のdual/不能判定は本探索の下界や枝刈りへ使わない。元モデルの点検査と有限の本来目的値、既存の証明下界チェックを通った候補だけincumbentへ渡す。親warmを更新せず、局所warmだけ更新する。初回主解がまだ無い場合に限り根で呼ぶ。MIP_FEASIBILITY_PUMP=0/1、最終版は既定有効。MIP_PUMP_CANDIDATE_DUMPに未存在ファイルを指定すれば候補を元目的/元変数名で保存できる。

## 開発問題、1 thread/16 GiB

最初の無条件版は固定18問でgmu-35-50の主解-2577545.7294→-2405838.0408へ悪化した。既存の主解を別の点で改善したことで後続RINS等の経路が変わったと考え、無条件版は不採用。原データを保持し、初回主解に限定した最終版では固定18問の主解/下界/statusが全て直前版と一致した。

binkar10_1の初回主解時刻を同CPU7、10秒制限で3回比較：

|無効|0.391115,0.391401,0.391198|0.391198|

約29.8%短い。最終主解7069.300014/下界6646.232386090788は同じ。最初のpump候補7412.420071も別ファイルへ保存してGMP/公式検査成功。初回点の質を同じと仮定した速度比較ではなく、最初に検査済みの実行可能点を得るまでの時間である。

追加開発6問を有効/無効で同CPU10秒比較。app1-1、app1-2、blp-ar98、glass4、mas74の主解/下界/statusは同じ。blp-ic98は無効で主解なし、有効で18526.1675168/下界4331.16835259805を発見。追加3回で同じ主解を0.56594/0.56885/0.57351秒に発見した。app1-1とglass4の本探索numerical_errorは残り、glass4の局所pumpにも数値失敗1件があったが候補/下界へ流用していない。app1-2は10秒内にpumpまで到達しなかった。一般整数のLP投影には未対応。

## 検証

初期有効版で2700合成MILP/300根LP/32数値回帰成功。初回限定の最終版でも1000 binary/500混合切断例を追加比較し成功。根LPの親基底が変化しないこと、丸め投影/循環回避、混合連続変数の点、期限経過、整数不能なモデルで候補を返さないことをRustテストで確認した。既定有効化でdiving/repair単独テストにpumpが作用して期待した「候補なし」と異なったため、他ヒューリスティックを明示的に無効化しているテスト群ではpumpも無効化し、173 Rustテスト成功。途中の失敗ログも保存する。

最終保存点・切断の再検査結果とsnapshot receiptは原データに保存する。全240問Rust snapshotはcreate-onlyで起動しない。次はpump候補の整数部分を固定し、本来の目的で連続部分を再最適化する汎用polishingを検討する。

独立再検査は保存58点でGMP/公式とも全件有効、76記録/322切除平面も全件有効。別保存した最初のpump候補1点のGMP/公式検査も成功し、保存された検査済み点は合計59。反復点を独立問題とは数えない。最終ソース08e89bd1（テスト分離コミットもsnapshotに含む）、experiments/feasibility-pump-snapshot-20261115.jsonにsource FNV/binary SHA/config SHAを保存。
