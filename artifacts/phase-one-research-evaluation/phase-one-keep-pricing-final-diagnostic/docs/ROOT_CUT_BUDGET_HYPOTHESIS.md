# 次の仮説：初回根LPと切断準備の予算を分ける

現在prepare_cutsは最初の根LPも切断準備の5%/最大0.25秒に含める。このため、基底回復に15秒かかるneos-860300や17秒のgermanrrでは、主探索で根LPを解けても切断候補を生成できない。

次の実験では、最初の根LPだけglobal期限を使い、その結果を切断処理または主探索へ引き継ぐ。切断候補生成と追加後の再最適化は従来の短い枠を使う。追加行の基底再利用は別の変更として先に検証した。

初回結果を保存して、同一の標準化Problemなら主探索で再求解しないことが重要。最適点だけでなくtime/numerical/infeasible等の結果も重複計算を避ける。切断を追加した時点で保存結果は無効化し、旧WarmStartのみ渡す。伝播有効時はglobal初回とキャッシュを使わず従来の短い切断準備経路を維持する。伝播なしの根だけは、取得時の標準化Problemと元変数/行の対応表を所有して主探索へそのまま渡し、再標準化も避ける。主探索での元点・目的・不能・下界の検証はそのまま通す。

期限直前に得た最適点を保存したのに主探索が先に停止しないように、キャッシュした根結果の通常の検証を一度だけ許す方式を検討する。これは追加LPを解く許可ではなく、取得済み結果の処理に限る。node_limit=0、期限0、伝播有効、cut rounds=0等の既存挙動をテストする。長いLPがcut準備側へ移るので、cut_seconds等の統計の意味も明記する。

比較対象は固定18問と開発側の回復した根LP。ネイティブ解を切断生成や初期点として使わない。目的格子が効くneosだけを狙った規則は作らない。悪化があれば保存して採否を判断する。
