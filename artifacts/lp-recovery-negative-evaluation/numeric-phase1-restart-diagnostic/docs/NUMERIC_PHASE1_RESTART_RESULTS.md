# 数値失敗後のPhase I再始動: 未採用

従来cold LPがNumericalErrorで終了した場合だけ、残り反復数・同じdeadlineでL1列重みのPhase Iを初期基底から実行する案を試した。旧失敗のstatsを加算し、仕事を返さない。成功したLP、通常の時間制限、warm成功は再始動しない。normalized側が失敗/規定の仕事上限に達した場合は既存の通常価格付けfallbackを使う。

main45257f737/FP3365の凍結版と同CPUで元MPSの純LP根診断を比較した。niddaは79→400 pivotsとなるが数値失敗のまま。kumeuは10秒で従来数値停止→時間制限となっただけで点はなく、60秒でも14,126→46,555 pivots・約9.5→35.2秒で数値停止した。uccase9は10秒/60秒とも再試行で時間制限まで進んだだけで点なし（60秒33,271 pivots）。これらを改善として数えない。

ranは3,476 pivots・LP境界3444.42106643829、app1は4,065 pivots・LP境界−22.824355359110097で前後同じ。両問題の前後4LP点を元MPSのFractionでbounds/rows/目的値照合する。整数解ではない。neos860300は前後とも10秒で根LP未完了、再始動は未発動。全例development、holdout利用なし。全体的な主解/最適証明の改善がないため未採用。許容差、復元回数上限、原問題証明は変更していない。

raw artifactsはnumeric-phase1-restart-*。直前のdual-tableau-refinement branchには双対逆積と失敗時primal方向の残差補正の棄却結果を保存した。次は復元回数が単純にLP全体で4回に制限されることが、意味のある進捗後の独立な回復も阻んでいないかを調べる。単に上限を増やす案は過去に失敗しているため、進捗と連続失敗を分ける必要がある。
