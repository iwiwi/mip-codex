# 双対tableauの残差補正

PR72の失敗時安定pivot再試行でもniddaの根LPは数値停止する。旧診断ではB^-T e_rと列の内積が選んだ候補の符号が、B^-1 a_jの実pivotで反転していた。基底逆積の丸め誤差が仮説。許容差や元問題証明を緩めず、失敗時再試行のSTABLE経路だけで元の基底列を使う厳密dot残差と反復補正を試す。成功した従来経路には追加処理を入れない。まずniddaとranの純LPで出力点をFraction検査し、neos860300等の既存回帰を維持する。新しい解/証明が得られなければ採用しない。外部の最適化処理は比較・検証に限る。holdoutは使わない。

最初の試行はSTABLE双対再試行中のB^-T e_rとB^-1 a_jだけを最大3回、exact dotで測った相対残差が改善する場合のみ補正した。niddaは79 pivots/4復元成功のまま数値停止し変化なし。ranは3476 pivots、3444.42106643829のLP境界を維持。旧dualの符号不一致自体はPR72の安定候補再試行で回避できており、現在のnidda停止は4回の復元上限だった。次は通常primalの比率検査がfresh LUと既存の点補正の両方で失敗した場合だけ、方向B^-1 a_jの残差補正を試す。復元上限や許容差は変えない。

通常primal方向の失敗時補正もniddaは79 pivots/4復元成功のまま。相対残差は1e-16台から小さくなるが進行を回復しない。ranの有効LP点・境界・3476 pivotsを維持するだけであり、両案とも性能改善として採用しない。両案のran前後4点は元MPSのFraction検査でLP実行可能性と目的値を照合する。整数解を得たとは扱わない。次は元のPhase Iが数値エラーで終わった場合だけ異なる価格付けからcold再始動する汎用案を別branchで試す。
